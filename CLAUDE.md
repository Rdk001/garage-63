# GARAGE 63 — PROJECT RULES

## Language
Всегда отвечай пользователю на русском языке.
Код, имена переменных, классов и технические идентификаторы оставляй на английском.

## Working style
Если задача понятна и согласована — выполняй её самостоятельно до логического завершения.

Не спрашивай подтверждение перед каждым:
- чтением файла;
- поиском по проекту;
- git status;
- git diff;
- git log;
- git branch;
- безопасной локальной проверкой;
- небольшим редактированием, непосредственно необходимым для поставленной задачи.

Не показывай предварительные diff только ради согласования.
После изменений используй git diff для самопроверки.

Не повторяй пользователю уже согласованный план.
Не пересказывай весь проект после каждого действия.
Экономь токены.

## Safe autonomous actions

Можно самостоятельно:
- читать любые файлы проекта;
- искать код и текст внутри проекта;
- использовать ls/find/grep/read/cat;
- использовать git status/diff/log/branch;
- проверять синтаксис;
- запускать безопасные локальные тесты;
- запускать локальный HTTP server;
- делать GET/curl к localhost;
- создавать и редактировать файлы внутри проекта, если это необходимо для текущей согласованной задачи.

## Forbidden without explicit user permission

Никогда самостоятельно не выполнять:
- git commit;
- git push;
- git reset --hard;
- git clean;
- force push;
- rebase;
- удаление существующих файлов;
- изменение истории Git;
- установку npm/pip/system dependencies;
- изменение production infrastructure;
- изменение production API/CORS;
- реальные POST/PUT/PATCH/DELETE запросы к production;
- публикацию/deploy проекта.

Также без отдельного разрешения не изменять:
- server.js;
- worker/index.js;
- wrangler.jsonc;
- GitHub Actions/workflows.

## Existing functionality that must not break

Всегда сохранять:
- форму заявки;
- маску телефона;
- валидацию телефона;
- существующий Cloudflare Worker endpoint;
- Telegram integration;
- адаптивность;
- GitHub Pages compatibility;
- fallback HTML;
- fallback при ошибке загрузки site.json.

Frontend сейчас размещается на GitHub Pages.
Production API находится на другом origin в Cloudflare Worker.

Не заменять production endpoint на /api/contact без отдельного изменения архитектуры.

## Editing rules

Перед изменением файла сначала изучи соответствующий существующий код.

Изменяй минимально необходимый участок.

Не форматируй весь файл ради небольшого изменения.

Не меняй:
- пробелы;
- комментарии;
- переносы строк;
- порядок существующего кода;

если это не требуется задачей.

Не перезапиши большой существующий файл целиком, если достаточно точечного изменения.

После редактирования обязательно самостоятельно просматривай git diff.

Если diff содержит неожиданные изменения — исправь их до отчёта пользователю.

## Commercial template architecture

Garage 63 постепенно превращается из демонстрационного сайта автосервиса в коммерческий переиспользуемый HTML-шаблон.

Используем гибридную архитектуру:
- существующий HTML содержит полноценный fallback;
- критический SEO-контент присутствует непосредственно в HTML;
- site.json используется для безопасной кастомизации;
- ошибка загрузки site.json не должна ломать страницу;
- theme.css используется для переопределяемой темы;
- новые динамические возможности не должны делать сайт зависимым от JavaScript для базового отображения.

Главный принцип:
сайт должен оставаться рабочим даже при отказе дополнительной конфигурации.

## Development priorities

При улучшении сайта приоритет:

1. Не сломать существующий рабочий функционал.
2. Профессиональный внешний вид.
3. Конверсия посетителя в заявку.
4. Mobile UX.
5. Производительность.
6. SEO.
7. Простая кастомизация под другого клиента.
8. Минимум зависимостей.
9. Простота поддержки.

Не добавляй сложность только потому, что технически это возможно.

## Demo content

Если используются вымышленные:
- отзывы;
- рейтинги;
- акции;
- статистика;
- сертификаты;

они должны быть явно обозначены как демонстрационные и не должны выглядеть как реальные подтверждённые данные бизнеса.

## End-of-task procedure

После выполнения задачи:

1. самостоятельно проверь изменения;
2. просмотри git diff;
3. убедись, что нет случайных изменений;
4. не делай commit/push;
5. дай короткий отчёт:

Изменено:
- ...

Проверено:
- ...

Проблемы:
- нет / описание проблемы.

После этого остановись и жди следующей задачи.

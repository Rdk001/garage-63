# Safe Edit

## Назначение

Безопасное внесение изменений в существующий стабильный проект.

## Workflow

1. Сначала изучить только необходимые файлы.
2. Перед изменением определить точную причину проблемы.
3. Не делать unrelated refactor.
4. Предпочитать минимальный diff.
5. Не менять стабильные компоненты без необходимости.
6. Сохранять существующий visual language и responsive architecture.
7. После изменений выполнить подходящие лёгкие проверки:
   - `git diff --check`;
   - syntax check изменённого JS, если JS менялся;
   - `git diff --stat`;
   - `git status --short`.
8. Browser/headless/Lighthouse запускать только когда задача действительно требует визуальной или runtime-проверки.
9. Не делать `git add`, commit или push без отдельного прямого разрешения.
10. Никогда не добавлять AI attribution в инструкции пользователю. Если Claude Code не может создать commit без `Co-Authored-By`, оставить изменения незакоммиченными и сообщить, что commit нужно выполнить вручную.
